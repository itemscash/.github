# **1. 概述与愿景**

## **1.1 项目简介**

items.cash 是一个基于全球 CS2（Counter-Strike 2）饰品交易市场构建的 **跨体系价值清算网络**。
 通过“法币 → 游戏饰品 → USDT”的价值转移路径，items.cash 为商户提供 **无需支付牌照的安全收单能力**。

项目核心创新：

- **以饰品作为价值锚点**（虚拟资产）
- **自动化凑单引擎**将任意支付金额转换为饰品组合
- **内部 USDT 拍卖系统**作为出货渠道
- **商户获得最终 USDT 结算**
- **无需直接接触法币**，规避传统支付风控链路

items.cash 旨在提供一种 **不依赖银行、不依赖二清、不依赖传统支付渠道** 的跨平台结算方法。

------

# **2. 产业背景与痛点**

## **2.1 全球虚拟物品交易规模**

- CS2 饰品年交易额超过 **百亿美元级别**
- BUFF163、IGXE、C5、Skinbaron、CSMoney 等平台用户量巨大
- 虚拟物品已经成为某种形式上的 **类资产**

## **2.2 传统收单存在的痛点**

| 痛点         | 描述                           |
| ------------ | ------------------------------ |
| 牌照要求高   | 获取支付/二清牌照难度极大      |
| 支付风控严格 | 金额敏感、地域限制、黑产高风险 |
| 商户接入麻烦 | 审核严格，资金冻结周期长       |

## **2.3 饰品具备天然的价值承载能力**

饰品价格透明、流动性强，可跨平台自由流转，是理想的“价值载体”。

items.cash 让饰品成为 **清算通道**。

------

# **3. 系统整体架构**

以下为系统五大核心组成部分：

### **① 订单创建子系统**

用户输入金额 → 生成支付订单

### **② 自动凑单引擎**

系统自动从 BUFF、IGXE、C5 等多个平台购买等值饰品

### **③ 支付二维码分发系统**

截取交易平台的付款二维码 → 传给用户完成支付

### **④ 饰品托管与内部拍卖市场**

饰品被放入 items.cash 库存 → 80% 底价拍卖 → 用 USDT 竞价

### **⑤ 商户 USDT 结算系统**

商户获得最终的 USDT 清算款，完成跨系统价值转移

------

# **4. 业务流程详解**

以下为完整闭环流程：

------

## **4.1 用户创建支付订单**

用户通过 API 或网页输入：

- 支付金额（如 ¥100）
- 支付方式（支付宝 / 微信 / 银行卡）
- 商户订单号
- 业务备注

items.cash 创建订单 → 进入自动凑单阶段。

------

## **4.2 自动凑单阶段**

凑单引擎执行以下步骤：

1. 抓取多个平台饰品实时价格
2. 使用 **最优组合算法（背包算法 / DP / 贪心 hybrid）**
3. 构建与支付金额接近的“饰品组合”
4. 自动下单购买饰品
5. 获取交易平台生成的支付二维码
6. 替换二维码 → 返回用户支付

此过程全自动。

------

## **4.3 用户支付 → 平台放行**

- 用户扫描二维码付款
- BUFF / IGXE / C5 收到支付后放行饰品
- 饰品自动进入 items.cash 的库存
- items.cash 订单状态更新为 **已入库**

此时 items.cash 已经拥有了价值载体。

------

## **4.4 内部拍卖市场（核心价值转换机制）**

饰品进入平台后：

- 系统自动生成拍卖单
- 底价 = 购买价 × **80%**
- 支持用户使用 **USDT 出价**
- 拍卖时间：N 分钟（可配置）
- 最高价者成交

拍卖结束：

- 购买者获得饰品
- items.cash 获得 USDT

------

## **4.5 商户获得 USDT 结算**

商户可以通过：

- Solana USDT 提现
- TRC20/ETH ERC20 提现
- 或者留存在余额用于下一次抵扣手续费

至此完成：

**人民币 → 饰品 → USDT 的价值迁移**

------

# **5. 自动凑单与价值映射机制**

该系统的核心任务是：

> “把任意金额的支付，映射为最合适的饰品组合”

### 技术指标：

| 指标       | 要求                        |
| ---------- | --------------------------- |
| 价格误差   | ≤ 2%                        |
| 平台覆盖   | BUFF / IGXE / C5 / 其他平台 |
| 最优解方式 | 多目标优化                  |
| 时间限制   | <3 秒构单                   |

### 核心逻辑：

- 优先选择 **高流动性饰品**
- 优先选择 **价格稳定性强的物品**
- 避免垃圾物品/滞销物品进入库存

------

# **6. 拍卖市场模型**

拍卖市场是 items.cash 的关键流动性组件。

### **拍卖规则**

- 起拍价 = 80% 买入价
- 加价幅度：1–5% 可配置
- 时间：10-60 分钟
- 最高价中标
- 用户通过 USDT 支付

### **用户群体**

- 想低价买入饰品的玩家
- 批量倒货的套利者
- 想通过 USDT 换饰品的用户

### **平台收益来源**

- 拍卖加价差
- 手续费
- 未成交饰品的折价复购

------

# **7. 商户结算体系**

### 商户可以：

- 创建订单
- 查询订单
- 获取支付回调
- 结算 USDT

系统提供：

- **商户 API Key / Secret**
- **Webhook 订单回调**
- **余额提取接口**

------

# **8. 手续费与收益模型**

items.cash 收益构成：

| 收益项               | 描述                 |
| -------------------- | -------------------- |
| ① 拍卖成交价差       | 理论利润主要部分     |
| ② 商户手续费         | 如 1%–3%             |
| ③ 存量饰品的浮动溢价 | 来自市场波动         |
| ④ 聚合交易平台返佣   | 部分平台提供购入返利 |

平台可以设置：

- 商户等级费率
- 大额用户费率
- 暗拍流动性矿池

# **9. 风控体系**

items.cash 必须包含以下风控模块：

------

## 9.1 支付风控

- 订单频次限制
- 异常金额检测
- 黑名单用户筛查
- 设备指纹识别
- IP/地域风控

------

## 9.2 饰品风险监控

- 防止购买高波动饰品
- 剔除虚高价格
- 监控异常涨跌
- 流动性评级系统

------

## 9.3 拍卖反作弊

- 防止刷单、对敲
- 防止自买自卖套利
- 必要时人工审核

------

## 9.4 商户风控

- 商户 KYB/KYC
- 异常结算限制
- 可疑订单冻结

# **11.  API 概要**

### **1. 创建订单**

POST /api/order/create
 参数：

- amount
- notify_url
- merchant_order_id
- payment_method

------

### **2. 查询订单**

GET /api/order/query?id=xxx

------

### **3. 商户回调 Webhook**

系统将在支付完成 → 饰品入库时回调：

```
{
  "status": "success",
  "order_id": "...",
  "merchant_order_id": "...",
  "amount": "100",
  "usdt_settlement": false
}
```

------

### **4. USDT 提现**

POST /api/merchant/withdraw

# **12. 合规性与法律风险分析**

### items.cash 的核心优势：

- 不直接接触法币
- 不提供支付服务
- 不触碰金融牌照
- 只是完成饰品交易与资产间的置换

但仍需关注：

| 风险         | 描述                             |
| ------------ | -------------------------------- |
| 虚拟资产监管 | 各国对虚拟物品或数字资产态度不同 |
| 洗钱风险     | 必须建立强风控模型               |
| 税务问题     | 商户应申报其自身收入             |
| 合规备案     | 某些地区可能要求登记             |
